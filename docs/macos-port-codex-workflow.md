# macOS 开发阶段与 Codex 协作流程

本项目采用 **ChatGPT Brain → Codex 执行 → ChatGPT 审查 → 用户批准** 的工作方式。Codex 是本地实现者，不自行改变架构或安全边界。

## 1. 阶段路线

| 阶段 | 工作 | 交付/验收 |
| --- | --- | --- |
| 0 | macOS Orca 环境侦察 | 插件、CLI、SDK、RPC、权限实测报告 |
| 1 | Toolkit 平台适配层 | runtime/path/open/picker/SSH 适配；Windows 回归通过 |
| 2 | Accounts | Mac 远程账号列表、用量、切换通过 |
| 3 | Downloads | Mac 并行、续传、校验、密钥权限通过 |
| 4 | GPU ComfyUI | LaunchAgent、Tailscale、workflow、产物完整通过 |
| 5 | Godot/Blender/Unity | 每个应用单独适配和验收 |
| 6 | VRoid/Tripo、安全和发布 | 兼容性明确；安装、升级、卸载文档齐全 |

不要跳过阶段 0，也不要在一个 Codex 任务中同时实现多个阶段。阶段 0 不通过时先解决 Orca 兼容性阻塞，不继续编写功能代码。

## 2. 协作职责

### ChatGPT

- 维护架构决策和阶段计划。
- 每次只定义一个可独立验收的任务，明确文件范围、约束、测试和交付格式。
- 阅读 Codex diff 和测试结果，提出修正指令。
- 对安全、权限和平台兼容性作独立审查。

### Codex

- 在用户 Mac 本地的 facming/orca-tools 工作区执行。
- 开始前检查 git status、当前分支和未提交改动；不覆盖用户已有工作。
- 在独立分支开发，不直接推送 main。
- 先跑针对性测试，再跑仓库回归测试。
- 汇报改动文件、设计决定、测试命令/结果、未解决问题和风险；不得只说“完成”。
- 未经明确指令，不合并 PR、不改仓库安全策略、不触碰真实凭据。

### 用户人工审核

以下事项必须暂停并请求用户确认：Orca 插件授权/审核、TCC 文件权限、管理员权限、PF/防火墙或系统扩展、SSH 私钥和真实账号、删除/覆盖文件、项目同步冲突和任何可能破坏现有数据的操作。

## 3. Codex 通用约束

- 不读取、输出或复制 token、OAuth、SSH 私钥或真实配置。
- 不把本机路径、IP、账号或密钥写入示例和 Git。
- 不关闭 host-key 校验，不开放公网端口，不增加通用 shell。
- 不绕过 Orca 审核、签名、沙盒或 macOS TCC。
- 不为了通过测试伪造状态、降低校验或扩大权限。
- 不自动执行不可信项目脚本，不自动覆盖用户文件或清理未跟踪产物。
- 保留 Windows 行为和现有测试；任何公共逻辑重构都必须有 Windows 回归证据。

## 4. 阶段 0 的 Codex 任务边界

**第一个 Codex 任务只做只读侦察和报告，不实现移植代码。**

要求报告：

1. Mac Orca 版本、插件 manifest/API 兼容性和插件加载实测。
2. Orca app bundle、CLI、RuntimeClient SDK、数据目录的真实定位依据；报告需脱敏，不输出用户隐私路径或凭据。
3. 插件激活、远程 environment 连接和只读 RPC 传输层的测试结果。不得调用 accounts.list 或用量接口、不得读取/输出真实账号邮箱和用量；如确需验证真实账号 RPC，先向用户申请明确授权。
4. Node.js、Python、OpenSSH、Tailscale 的可用性和版本，不包含密钥/token。
5. 当前源码 Windows 专属依赖清单，按 Accounts、Downloads、GPU 分类。
6. Apple Silicon/Intel 架构和 GPU backend 能力（只报告实际检测结果）。
7. 阻塞项、风险、可行性结论，以及阶段 1 的最小设计建议。

不要在阶段 0 修改 Orca 安装包、写入用户 LaunchAgent、改防火墙/PF、安装系统扩展、创建密钥、登录账号或提交真实任务。需要人工授权的检查先停下来报告。

## 5. 每个阶段的交付格式

Codex 完成一个阶段后必须给出：

- **变更摘要**：做了什么、为什么这样做。
- **文件清单**：新增/修改/删除及关键行为。
- **测试**：执行命令、通过/失败数量、未执行项目及原因。
- **安全审查**：权限、密钥、网络监听、进程和文件覆盖边界。
- **人工步骤**：需要用户点击、授权或在真实 Mac 上验证的事项。
- **剩余问题**：不能隐瞒的限制、风险和后续任务。
- **Git 状态**：分支、commit、是否推送、PR 地址；未经批准不合并。

ChatGPT 审查通过后再安排下一阶段。用户确认后合并 PR。
